# 使用指南

面向**已经在自己的 Cloudflare 账号上部署好实例**的人。部署本身见 [deploy.md](deploy.md)，
给接入方看的 OIDC 集成见 [下游集成.md](下游集成.md)。

本文只讲：作为**使用者**和**管理员**，这平台怎么用。

---

## 0. 先弄清三种角色

平台没有"注册即用"，所有人都是被邀请进来的。

| 角色 | 能做什么 | 怎么得到 |
|---|---|---|
| `user` | 登录、改密码、绑 MFA、管理自己的会话 | 邀请码注册，或被升级 |
| `admin` | 上面全部 + 查看用户/邀请/应用/会话/审计、启禁用账号、踢人下线 | 超管在「用户」页改角色 |
| `super_admin` | 上面全部 + 改角色、重置他人 MFA、增删 OIDC 客户端、轮换密钥 | 种子脚本创建，或现有超管升级 |

**关键约束**：`super_admin` 在绑定任意第二因子（TOTP 或 Passkey）之前，
**进不了任何 /admin 页面**，会被锁在 `/account/security` 要求先绑定。

这不是 bug。超管能看后台明文邀请码、能重置任何人的 MFA——
不强制 MFA 的话，一条泄露的密码就等于整个租户沦陷。

## 1. 第一次登录

### 1.1 拿到初始账号

部署时已经用 GitHub Secrets 里的 `SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD` 建好了第一个超管。
密码就是你在 Secrets 里填的那个，**不会强制你修改**（它是你自己设的，不是系统生成的临时口令）。

### 1.2 绑定第二因子（超管必须做）

访问 `https://<你的域名>/login`，用上面那组邮箱密码登录。
登录成功后会被直接送到 `/account/security`，因为超管还没绑 MFA。

两种绑定方式，**任选其一即可满足门禁**：

**TOTP（推荐先用这个）**
1. 点「启用 TOTP」
2. 用验证器 App（1Password / Authy / Google Authenticator / Aegis 都行）扫二维码
3. 输入 App 显示的 6 位数字，点「确认启用」
4. **立刻保存页面上显示的那 10 个恢复码**——只显示这一次

**Passkey**
1. 点「绑定新设备」
2. 按系统弹窗完成指纹 / 面容 / PIN 验证

> Passkey 绑定失败（移动端常见 `NotReadableError`）时，先绑 TOTP 把门禁过了，
> 之后再回来补绑 Passkey。两者权重相同，不要求都绑。
>
> 系统弹窗里显示的站名来自 `RP_ID`。如果显示成一串网址，
> 检查 `wrangler.toml` 里的 `ISSUER` 结尾有没有多余的斜杠。

### 1.3 建第二个超管（强烈建议）

**只有一个超管 = 这个人失联就全租户锁死。**

超管能重置别人的 MFA，但**没有任何人能重置超管的 MFA**（除了另一个超管）。
所以：`/admin/invites` 生成一个 `admin` 角色的邀请码，注册后到 `/admin/users` 把他改成 `super_admin`。

## 2. 邀请新人加入

平台**不发邮件**，邀请码靠你自己转发。

### 2.1 打开邀请功能

邀请默认关闭。在 `packages/gateway/wrangler.toml` 里设：

```toml
[vars]
INVITE_ENABLED = "true"
```

重新部署 gateway 才生效（`deploy-quick.yml` → `target=gateway` 就够）。

关闭状态下 `POST /auth/invite/accept` 直接 404，不暴露端点存在。

### 2.2 生成邀请码

`/admin/invites` → 填「限定邮箱」（可选）和「初始角色」→ 生成。

**邀请码明文只显示这一次**，之后的列表里只有状态，看不到码。

| 字段 | 说明 |
|---|---|
| 限定邮箱 | 填了就只允许这个邮箱使用；留空则任何持码者可用 |
| 初始角色 | `user` 或 `admin`。**没有 super_admin 选项**，超管只能事后升级 |
| 有效期 | 7 天 |
| 使用次数 | 一次 |

生成后**直接复制**转给对方（微信、Signal、线下都行）。页面不会再次显示它。

### 2.3 对方怎么用

对方打开 `https://<你的域名>/register`：

1. 填邀请码、邮箱、密码（**至少 12 位**）
2. 点「创建账号」
3. 自动跳回登录页

登录页底部有「用邀请码注册」的入口，找不到可以直接访问 `/register`。

## 3. 日常使用

### 3.1 登录

`/login` 有两种方式：

- **邮箱 + 密码** → 如果绑了第二因子，会跳到 `/mfa` 要验证码
- **使用 Passkey 登录** → 免密，直接进

Passkey 登录走的是"可发现凭证"（resident key），浏览器会弹出账户选择器，
**不需要先输入邮箱**。

### 3.2 二次验证页

密码登录后如果看到 `/mfa`，说明还差一步。三个选项：

| 方式 | 什么时候用 |
|---|---|
| 输入 6 位验证码 | 手机在身边的常态 |
| 使用 Passkey | 手机丢了但电脑上还有绑定过的 Passkey |
| 使用恢复码 | 验证器和 Passkey 都没了——**最后的出路** |

恢复码格式 `xxxxx-xxxxx`，**每个只能用一次**。用完后记得到 `/account/security` 重新生成。

### 3.3 我的账户

`/account`（普通用户和管理员都能进）：

- 当前绑了哪些第二因子
- 恢复码剩余几个
- 去改密码 / 安全设置的入口

### 3.4 改密码

`/account/password`，需要输入**当前密码**。

改完之后：
- 其它所有会话、访问令牌、在途授权码**全部吊销**
- 当前这条会话保留，但 token 会轮换（你不会被踢下线）

### 3.5 退出登录

点退出会**同时吊销服务端会话**，不只是清浏览器 Cookie。
被别人用过的设备一定要点退出，光关浏览器不算。

## 4. 管理员操作

### 4.1 用户管理 `/admin/users`

| 操作 | 谁能做 | 效果 |
|---|---|---|
| 禁用 / 启用 | admin | 禁用会**连带吊销该用户全部会话与令牌** |
| 踢下线 | admin | 吊销全部会话，但不禁用账号 |
| 重置 MFA | **仅超管** | 吊销全部因子 + 全部会话，用户下次登录要重新绑 |
| 改角色 | **仅超管** | 见下面的约束 |

**角色约束**：

- admin **不能**禁用或踢超管（会被 403）
- **不能禁用最后一个活跃超管**（会把整个实例锁死）
- **不能降级最后一个超管**

这三条是同一件事的三个入口，都堵上了。

### 4.2 重置某个人的 MFA

用户手机丢了、验证器没了、恢复码也用光了 → 管理员来救。

`/admin/users` → 找到那行 → 「重置 MFA」。

这会：
- 把该用户**所有** TOTP 因子标记为已吊销（包括**尚未确认的 pending 因子**）
- 吊销所有 Passkey
- 删掉所有恢复码
- 吊销所有会话

用户下次登录会因为"没有任何第二因子"而直接进入，然后被引导去重新绑定。

> 只有超管能做这一步。admin 点不动。

### 4.3 活动会话 `/admin/sessions`

看当前所有活跃会话：谁的、什么时候建的、最后活动时间、IP、User-Agent。

"最后活动"是真实的——每次带会话的请求都会更新它。

### 4.4 审计 `/admin/audit`

登录成功/失败、MFA 绑定与验证、改密、角色变更、邀请生成与使用、客户端增删、
令牌签发、MFA 被重置……都在这里。

保留 60 天，之后由 cron 分批清理。

**审计写入失败不会阻断业务**——它刻意做成 best-effort，否则数据库抖动会导致登录全挂。

## 5. 接入自己的应用（OIDC）

完整参数见 [下游集成.md](下游集成.md)，这里只讲后台操作。

### 5.1 创建客户端

`/admin/apps`（**仅超管**）→ 填应用名称 + 回调地址 → 创建。

回调地址：
- **每行一个**
- **精确匹配**，不支持通配符
- 必须带协议（`https://` 或本地开发的 `http://localhost:PORT`）

创建后页面会显示 `client_id` 和 `client_secret`。

> **密钥只显示这一次。** 刷新就没了，只能轮换重新生成。

### 5.2 轮换密钥

`/admin/apps` → 对应行 → 「轮换密钥」。

**旧密钥立刻失效**，下游必须马上更新。没有过渡期。

### 5.3 你需要告诉接入方的四件事

| 项 | 值 |
|---|---|
| Issuer | `https://<你的域名>` |
| Discovery | `https://<你的域名>/.well-known/openid-configuration` |
| client_id | 创建时给的 |
| client_secret | 创建时给的（只此一次） |

支持的 scope 只有三个：`openid`（必需）、`profile`、`email`。
只支持授权码 + PKCE（S256），不支持隐式流、不支持 client_credentials。

## 6. 出问题了怎么办

### 6.1 我把自己锁在外面了

| 症状 | 原因 | 解法 |
|---|---|---|
| 登录后一直被送到 `/account/security` | 超管没绑 MFA | 绑 TOTP 或 Passkey，见 1.2 |
| 验证码一直不对 | 设备时间偏差超过 30 秒 | 打开系统"自动设置时间" |
| 恢复码也全用完了 | —— | 找**另一个超管**重置你的 MFA |
| 只有一个超管，且他进不去 | 全租户锁死 | 只能直接改库，见 runbook |

### 6.2 密码一直提示错误，但我确定是对的

先确认不是被限流。当前实现里：

- **同一 IP** 1 小时内失败 20 次 → 该 IP 被拒
- **同一账号** 15 分钟内失败 10 次 → **只记不拦**（仍然可以用正确密码登录）

如果换网络能进，就是 IP 被限了，等 1 小时或换个网络。

> 账号维度故意不阻断登录：否则任何人只要知道你的邮箱，
> 每 15 分钟提交 10 次错误密码就能让你永远进不来。

### 6.3 Passkey 绑定失败

按错误信息对症：

| 报错 | 原因 |
|---|---|
| `NotAllowedError` | 你点了取消，或者超时了 |
| `SecurityError` | 当前域名和 `RP_ID` 不匹配——用正式域名访问，别用 IP |
| `InvalidStateError` | 这台设备已经绑过了。换设备，或先在系统设置里删掉旧凭证 |
| `NotReadableError` | 手机没设屏幕锁 / 密码管理器没开 / 在工作资料或无痕模式里 |

绑不上就先绑 TOTP——**同样满足超管门禁**，不要求两个都绑。

### 6.4 密钥泄露了

**`SESSION_PEPPER` 泄露** → 所有密码哈希都等于明文。
必须：立刻轮换 pepper，然后**所有人都得重设密码**（旧哈希全部失效）。

**`TOTP_MASTER_KEY` 泄露** → 已加密的 TOTP secret 可能被解出。
轮换后已有 TOTP 因子无法解密，需要逐个重置 MFA。

**`SIGNING_KEYS_JSON` 泄露** → 有人能伪造 ID Token。
在下游缓存过期前轮换，并把新密钥放到数组首位、旧密钥保留一段时间。

## 7. 一些反直觉的行为（都是有意设计的）

**登录成功不会清 IP 桶**
只清账号桶。否则攻击者用自己账号登录一次，就能把自己 IP 的失败计数清零。

**账号输错 10 次不会被锁死**
只记录、不阻断。见 6.2。

**改密码不会把自己踢下线**
当前会话保留并轮换 token。

**用恢复码登录会踢掉其它所有会话**
恢复码被使用 = 凭证可能已丢失，所以视为"账号接管"，其余会话全部作废。

**超级管理员的密码不是万能的**
没绑第二因子就进不了后台。绑了之后，密码只是第一道。

**ID Token 签发后无法吊销**
OIDC 协议本身的限制。接入方必须以访问令牌（可内省、可吊销）为准，
不能把 ID Token 当长期凭证。

## 8. 规模与边界

- **≤ 10 人**：管理列表分页上限 25，是 Workers 免费版 10ms CPU 预算决定的
- **单租户**：没有 `tenant_id`，所有应用共享同一批用户
- **不发邮件**：邀请码、密码全靠线下转达
- **没有自助找回密码**：忘了密码只能找管理员

超出这些范围的场景，见 [SECURITY.md](../SECURITY.md) 的"不适用于"一节。
