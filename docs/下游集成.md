# 下游应用集成指南

> 给接入本 SSO 的应用开发者。**第 4 节是义务，不是建议。**

## 1. 注册客户端

由超管在 `/admin/apps` 或通过具名方法创建，需要提供：

- 应用名称
- **回调地址**（`redirect_uris`，精确匹配，不支持通配符）
- 登出后跳转地址（`post_logout_redirect_uris`，可选）

返回 `client_id` 与 `client_secret`。**secret 只显示一次**，请立即保存。

## 2. 端点

从 `{issuer}/.well-known/openid-configuration` 获取，不要硬编码。

| 端点 | 路径 |
|---|---|
| 授权 | `/oauth/authorize` |
| 令牌 | `/oauth/token` |
| 用户信息 | `/oauth/userinfo` |
| JWKS | `/oauth/jwks.json` |
| 内省 | `/oauth/introspect` |
| 撤销 | `/oauth/revoke` |
| 登出 | `/oauth/logout` |

## 3. 授权码流程

### 3.1 发起授权

```
GET /oauth/authorize
  ?client_id=<client_id>
  &redirect_uri=<回调地址，必须精确匹配>
  &response_type=code
  &scope=openid profile email
  &state=<随机串，必须校验回传>
  &nonce=<随机串，会写进 ID Token>
  &code_challenge=<S256 后的值>
  &code_challenge_method=S256
```

**`state`、`nonce`、PKCE 三者都是强制的。** 缺少任何一个，服务端直接返回 400。

`code_challenge` = `BASE64URL(SHA256(code_verifier))`，`code_verifier` 为 43–128 字符随机串。

### 3.2 换取令牌

```
POST /oauth/token
Content-Type: application/x-www-form-urlencoded

grant_type=authorization_code
&client_id=<client_id>
&client_secret=<client_secret>
&code=<回调收到的 code>
&redirect_uri=<与授权时完全一致>
&code_verifier=<原始 verifier>
```

响应：

```json
{
  "access_token": "不透明字符串",
  "token_type": "Bearer",
  "expires_in": 3600,
  "id_token": "EdDSA 签名的 JWT",
  "scope": "openid profile email"
}
```

授权码 **60 秒有效、单次使用**，重放会返回 `invalid_grant`。

## 4. 下游义务（必须遵守）

### 4.1 不要把 ID Token 当长期授权依据

ID Token 是签名 JWT，**签发即不可收回**。它只用于「这次登录是谁」。

调用自己的 API 时必须用 `access_token` 走 `/oauth/userinfo` 校验，不要解码 ID Token 后自己再签一个长效 token —— 那样我们的吊销传不到你这里。

### 4.2 内省缓存不得超过 60 秒

```
POST /oauth/introspect
Content-Type: application/x-www-form-urlencoded

client_id=<client_id>&client_secret=<client_secret>&token=<access_token>
```

| 你的行为 | 吊销生效时间 |
|---|---|
| 每次请求都内省 | 即时 |
| 缓存 ≤ 60 秒 | ≤ 60 秒 |
| 缓存 > 60 秒 或 不内省 | **吊销对你不可见** |

对无效、已吊销、已过期的令牌，一律返回：

```json
{ "active": false }
```

**不会告诉你原因**——这是刻意的，避免成为令牌探测接口。

### 4.3 用户登出要调撤销端点

```
POST /oauth/revoke
Content-Type: application/x-www-form-urlencoded

client_id=<client_id>&client_secret=<client_secret>&token=<access_token>
```

按 RFC 7009，无论 token 是否存在都返回 200。

## 5. 验证 ID Token

```ts
// 1. 从 {issuer}/oauth/jwks.json 取公钥（缓存建议 5 分钟）
// 2. 按 header.kid 选公钥
// 3. 用 Ed25519 验签

const ok = await crypto.subtle.verify(
  "Ed25519",
  publicKey,
  signature,
  new TextEncoder().encode(`${header}.${payload}`),
);
```

必须校验的声明：

- `iss` 等于 discovery 里的 issuer
- `aud` 等于你的 client_id
- `exp` 未过期
- `nonce` 等于你发起的值（防重放）

`sid` 是本会话的稳定标识，现在可用于日志关联，将来若补 Back-channel Logout 会用到。

## 6. 登出

```
GET /oauth/logout?client_id=<client_id>&post_logout_redirect_uri=<地址>
```

`post_logout_redirect_uri` 必须在该客户端注册的白名单内，否则不跳转。

## 7. 常见错误

| 错误 | 原因 |
|---|---|
| `invalid_redirect_uri` | 回调地址与注册值不完全一致（**不重定向，直接报错**，防开放重定向） |
| `invalid_grant` | 授权码已用、已过期（>60s）、client 不匹配或 PKCE 校验失败 |
| `invalid_client` | client_secret 错误 |
| `unsupported_grant_type` | 只支持 authorization_code，**不签发 refresh token** |

## 8. 没有 refresh token 怎么办

访问令牌 1 小时过期后，**让用户重新走一次 `/oauth/authorize`**。

因为 SSO 会话 Cookie 还在（7 天），这次跳转是**静默的**：浏览器直接带着会话完成授权，用户只看到一次快速跳转，不需要重新输密码。

这是用「即时可吊销」换来的简化——比引入 refresh token 的轮换与重放检测简单得多。
